# info.toml 规范

每个专辑文件夹（`res/[专辑名]/`）中应包含一个 `info.toml` 文件，用于存储专辑的元数据信息。

## 文件格式

`info.toml` 使用 TOML 格式，包含以下字段：

```toml
年份 = "2024"
出品 = "五维介质Official"
发布 = "https://example.com/release"
购买 = "https://example.com/buy"
演唱 = ["苍穹", "Melo"]
作词 = ["苍穹"]
作曲 = ["Melo"]
调校 = []
发布 = ""
购买 = ""
```

## 字段说明

| 字段 | 类型 | 是否必需 | 说明 |
|------|------|--------|------|
| 年份 | 字符串 | 否 | 专辑发行年份，格式为 YYYY |
| 出品 | 字符串 | 否 | 专辑出品方/发行方 |
| 演唱 | 数组 | 否 | 演唱者列表 |
| 作词 | 数组 | 否 | 作词人列表 |
| 作曲 | 数组 | 否 | 作曲人列表 |
| 调校 | 数组 | 否 | 调校师列表 |
| 发布 | 字符串 | 否 | 发布页面URL（可缺省） |
| 购买 | 字符串 | 否 | 购买链接URL（可缺省） |

## 注意事项

1. **所有字段均为可选**
   - 如果字段不存在或值为空，在 README 中会显示"缺少信息"
   - 在专辑详情页的 tags 中会被忽略（空字段不添加tag）
   - 对于URL字段（发布、购买），缺省时不显示

2. **数组格式**
   ```toml
   演唱 = ["歌手1", "歌手2", "歌手3"]
   调校 = []  # 空数组表示"无信息"
   ```

3. **无信息标记**
   - 如果需要明确表示"无此信息"，使用 `"N/A"` 字符串
   - 默认情况下，缺失字段使用空数组 `[]` 或空字符串 `""`

4. **字符串和URL格式**
   ```toml
   出品 = "中术"
   发布 = "https://example.com/release"
   ```


## 示例

### 示例 1：完整信息
```toml
年份 = "2023"
出品 = "中术"
演唱 = ["言和"]
作词 = ["词作者A"]
作曲 = ["曲作者B"]
调校 = ["调校师C"]
```

### 示例 2：最小信息
```toml
年份 = "2024"
出品 = "中术"
演唱 = []
作词 = []
作曲 = []
调校 = []
```

### 示例 3：多人参与
```toml
年份 = "2023"
出品 = "中术"
演唱 = ["苍穹", "Melo", "其他"]
作词 = ["灰鸟", "Melo"]
作曲 = ["Melo", "某某"]
调校 = ["调校师A", "调校师B"]
```

## 集成方式

1. 在每个专辑的 `res/[专辑名]/` 目录下创建 `info.toml` 文件
2. 运行 `npm run generate-md` 命令自动生成文档
3. 脚本会自动读取 info.toml 并：
   - 在专辑详情页显示信息
   - 在 tags 中添加出品、演唱、作词、作曲、调校人员
   - 在首页 README 显示出品和发行年份

## 自动生成脚本

脚本位置：`.github/scripts/generate-md.js`

脚本会：
- 自动遍历所有 `res/` 下的专辑文件夹
- 如果 `info.toml` 不存在，则使用默认值
- 如果字段缺失，则省略该项
- 生成对应的 Markdown 文档

## 常见问题

**Q: 如果文件不存在怎么办？**
A: 脚本会使用默认值，在 README 中显示"未知"，在详情页和 tags 中忽略该项。

**Q: 可以有其他字段吗？**
A: 当前脚本只识别上述 6 个字段，其他字段会被忽略。

**Q: 如何更新已有的专辑信息？**
A: 修改对应的 `info.toml` 文件，然后运行 `npm run generate-md` 重新生成。
