# 调研记录

- [现状] 工作站每次投稿使用独立 `web/<session>/` R2 前缀，原始文件和 `manifest.json` 均写入该前缀。
- [现状] `res/单曲/` 已存在，摄取管道对显式专辑名 `单曲` 会进入增补模式。
- [风险] Worker 内部 `/store` 当前仍暴露受令牌保护的单对象和前缀删除能力，需要收窄为只读写。
- [依据] R2 目录只是对象键前缀；单曲目标需由上传类型和服务端校验共同约束，不能只依赖前端填写名称。
- [生产配置] `lrc-upload` 原有 `expire-web-payloads-30d` 生命周期规则，会让 `web/` 已完成上传在 30 天后过期，与本次保留要求冲突。
- [保留边界] Cloudflare 默认规则只在 7 天后中止未完成 multipart，不会删除已经完成的上传对象，应继续保留以免遗留分片占用空间。
- [服务端权威] `web/<ref>/manifest.json` 的 `submission_type` 是投稿类型权威；Runner 显式传给 Phase A，客户端 `manifest.toml` 的缺失或伪造不能改变单曲目标。
- [生产 Phase B] 稀疏克隆只包含 `.github`，临时 `res` 初始为空；单曲目录存在性必须沿用 Phase A 写入的不可编辑状态，不能在 Phase B 检查临时目录。
- [聚合目录边界] 单曲投稿只产出本次曲名对应的 `.lrc/.klrc`，无默认曲序前缀，不写 `meta.toml` 或封面，并跳过专辑元数据补全器。
- [删除边界] 完成的 `web/` 单对象和前缀删除均返回冲突；可再生的 `review/` 草稿清理和未完成 multipart 中止保持可用。
