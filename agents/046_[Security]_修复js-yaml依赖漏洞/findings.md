# 调研结论

- [当前依赖图] -> `gray-matter@4.0.3` 要求 `js-yaml@^3.13.1`，VuePress 插件要求 `js-yaml@^4.1.0` -> 必须保留两个主版本。
- [安全公告] -> v3 应升级到 `3.15.1`，v4 应升级到 `4.3.1` -> 两个版本分别覆盖已确认的 YAML 解析拒绝服务公告。
- [既有 PR] -> 使用单一全局 override -> 一份将 v4 消费者降到 v3，另一份将 `gray-matter` 升到 v4；两者的 `pnpm docs:build` 均失败。
- [首次配置编辑] -> 假定 `devDependencies` 位于文件末尾导致补丁上下文不匹配 -> 已停止并按当前文件结构重新定位，依赖配置未改变。
- [锁文件重解析] -> pnpm 按版本选择器将 v3 解析为 `3.15.1`、v4 解析为 `4.3.1` -> 两条依赖线均保留，旧版本均被替换。
- [锁文件噪声] -> pnpm 为未涉及的 `@ungap/structured-clone` 新增弃用元数据 -> 已移除，不将无关元数据混入安全修复。
- [依赖树命令] -> `pnpm list --lockfile-only` 不受当前 pnpm 支持 -> 改用冻结安装后的 `pnpm why` 核验实际解析树。
- [冻结安装] -> `pnpm install --frozen-lockfile --ignore-scripts` 成功 -> 锁文件与依赖声明一致，安装阶段未执行生命周期脚本。
- [构建与审计] -> `pnpm docs:build` 成功渲染 904 页，`pnpm audit --json` 未返回 `js-yaml` 公告 -> 修复保留兼容性并清除该包的已知审计项。
- [提交前关键词检查] -> 循环变量命名为 Zsh 特殊变量 `path`，覆盖命令搜索路径使 `rg` 未执行 -> 依赖文件未变，改用普通变量重跑检查。
